ITN-Pass v1.0.0 - installation notes
====================================

WHAT THIS IS
  ITN-Pass is the InterTeamNet disk-writer station: a password-protected
  station computer writes a prepared payload onto a floppy with a disk drive,
  and a terminal computer in front of it asks a visitor for an ITN-Pass
  credential before the write happens. Nothing is written without a valid
  credential - unless the station is switched to free mode (see RUN MODES).

  All user-visible text is plain ASCII English. The Chinese documentation is in
  README.md and docs/DISTRIBUTION.md; this file is the short, copy-paste guide.

PACKAGE LAYOUT
  itn-pass/README.md            - full manual (Chinese)
  itn-pass/DECISIONS.md         - design decisions and capacity numbers
  itn-pass/INSTALL.txt          - this file
  itn-pass/docs/DISTRIBUTION.md - batch / issuance / delivery workflow
  itn-pass/common/              - files shared by BOTH computers
  itn-pass/server/              - station computer only
  itn-pass/terminal/            - terminal computer only

  The package has no tests directory: tests/ is development material and is
  excluded from the release zip.

SERVER COMPUTER - deploy plan
  game path                     package path
  /startup.lua                  itn-pass/server/startup.lua
  /sha256.lua                   itn-pass/common/sha256.lua
  /itnpass_net.lua              itn-pass/common/itnpass_net.lua
  /itnpass_mode.lua             itn-pass/common/itnpass_mode.lua
  /itnpass_profile.lua          itn-pass/common/itnpass_profile.lua
  /auth/itnpass_config.lua      itn-pass/server/auth/itnpass_config.lua
  /auth/itnpass_store.lua       itn-pass/server/auth/itnpass_store.lua
  /system/itnpass_server.lua    itn-pass/server/system/itnpass_server.lua
  /system/disk_writer.lua       itn-pass/server/system/disk_writer.lua
  /system/itnpass_admin.lua     itn-pass/server/system/itnpass_admin.lua
  /payload/...                  your own files (path configurable via payload_dir)

  /sha256.lua, /itnpass_net.lua and /itnpass_profile.lua MUST sit at the ROOT of
  the server disk: the store does dofile("/sha256.lua"), the config does
  dofile("/itnpass_net.lua"), and the config / writer / service / batch tool do
  dofile("/itnpass_profile.lua"). Missing /sha256.lua prints
  "[ERROR] cannot load /sha256.lua" in the console; missing /itnpass_profile.lua
  raises the service fault flag and batch prints error=profile_unavailable.

HARDWARE
  Station: TWO wired modems, on two physically separate networks.
    Network A (terminal side): station modem + every terminal. Channel 33.
    Network B (drive side): station modem + exactly one disk drive, nothing else.
  Terminal: ONE wired modem on network A.
  Do not put the drive and the terminals on the same wire: CraftOS shares every
  peripheral with every computer on a wired network, so the "exactly one drive"
  test would stop meaning anything.

FIRST BOOT
  Station:  reboot the computer. The service starts and the admin console asks
            for a new password (minimum 4 characters) on first run; it is stored
            in /auth/itnpass_admin.db. The console prints MODE: pass|free.
  Terminal: reboot. It runs a network check first: it counts stations on the
            channel and passes only when exactly one station answers. On failure
            it locks the terminal and reboots into a bare shell.

RUN MODES
  pass (default) - every disk write needs a credential and charges one use.
  free           - public open mode: no credential, nothing is charged, the
                   terminal skips the login screen. Disk write validation,
                   rollback and space checks are identical in both modes.

  Switch without touching code: put the single word
      free
  (or "pass") into /auth/itnpass_mode.txt on the station AND on the terminal,
  then reboot both. That file wins over the mode field in the config. An invalid
  value in the file is rejected and the config value is kept, with ITNP_MODE_BAD
  logged to /auth/itnpass_mode.log.

  The two computers must agree: a terminal in free mode sends an empty
  credential, which a station still in pass mode rejects as "empty code".

PAYLOAD PROFILES
  A profile names the payload a disk write installs and its byte budget.
  Catalog: /itnpass_profile.lua. Names: default, pyroet-os, pyromputer-os.
    default       one tree (/payload), no profile byte budget
    pyroet-os     one floppy, one write transaction, 1,228,800 B budget
    pyromputer-os two floppies, two write transactions (one per part),
                  1,228,800 B per disk, payload under /payload/part1|part2
  Switch without touching code: put the single name
      pyroet-os
  into /auth/itnpass_profile.txt on the station, then reboot. It wins over the
  profile field in the config; an invalid value is rejected and logged as
  ITNP_PROFILE_BAD in /auth/itnpass_profile.log. Card keys made by
  "itnpass_batch new --profile NAME" only pay for that profile.
  Byte budget override: profile_capacity in /auth/itnpass_config.lua, for
  example { ["pyroet-os"] = 1000000 }.

EXPECTED LOG LINES (station console)
  ITNP_START ...          service started, channel/protocol reported
  ITNP_CHECK ...          a terminal asked to verify a credential
  ITNP_GRANT ...          credential accepted, one use reserved
  ITNP_WRITE ...          payload copied
  ITNP_COMMIT ...         use committed, uses_left reported
  ITNP_DENY / ITNP_LOCKED / ITNP_WRITE_FAIL   rejections and failures

COMMON FAILURES
  "cannot load /sha256.lua"        server disk is missing /sha256.lua at the root
  "cannot load /itnpass_net.lua"   server disk is missing /itnpass_net.lua
  "multiple servers: N"            more than one station answers on channel 33
  "no card key server detected"    station is off, on another channel, or the
                                   terminal modem is unwired (legacy wording,
                                   kept for compatibility with the old project)
  "modem_side '<x>' is not ..."    the configured modem side is wrong (server)
  "empty code"                     free-mode terminal talking to a pass station
  "payload too large"              payload above the profile budget; no use was
                                   charged, shrink the payload or change profile
  "unknown profile"                profile name not in /itnpass_profile.lua
  "profile mismatch"               the key is bound to another payload profile
  write fails with a size error    payload does not fit the floppy; shrink it

BUILD AND TEST (repository side, not needed in game)
  Build the release zip:
      python tools/build_release.py --project itn-pass --out dist/release
  Run the offline regression suite (needs CraftOS-PC):
      pwsh -NoProfile -File itn-pass/tests/run-tests.ps1
  Baseline: OFFLINE_PASS 1177 / OFFLINE_FAIL 0 / OFFLINE_GROUPS 60.
  The suite stages itn-pass/.offline and deletes it when it passes.

  The zip is reproducible: same inputs, same bytes. Do not write the zip size or
  its sha256 into a file that is itself inside the zip - the package documents
  are members of the package, so that would be self-referential.
